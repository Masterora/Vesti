# Vesti

[English](README.md) | [简体中文](README.zh-CN.md)

Vesti 是面向远程协作的里程碑式 USDC 托管产品，为需求方与工作者提供统一流程，用于约定交付内容、记录履约进度，并以可追溯的方式释放付款。

## 用户视角

### 需求方

需求方可以：

- 创建私有合约，或发布公开项目。
- 定义多个里程碑，并确保里程碑金额之和等于合约总额。
- 选择工作者、为托管账户注资并跟踪交付进度。
- 查看每一版交付证明、请求修改、批准成果并释放付款。
- 对进行中且尚未付款的里程碑发起争议。

### 工作者

工作者可以：

- 加入被直接分配的合约，或申请公开项目。
- 查看里程碑范围、金额、截止日期和合约历史。
- 提交交付证明，且不会覆盖以前的版本。
- 响应修改请求，并跟踪批准和付款状态。
- 对进行中且尚未付款的里程碑发起争议。

双方均使用钱包地址标识身份。系统根据用户角色和当前合约状态，只展示其有权执行的操作。

## 用户流程

1. 需求方定义工作内容和里程碑。
2. 工作者由需求方直接指定，或从公开项目申请者中选定。
3. 需求方为托管账户注资，合约随即生效。
4. 工作者提交当前里程碑的交付证明。
5. 需求方批准证明，或请求修改。
6. 已批准的资金释放给工作者。
7. 重复上述流程，直至所有里程碑均完成付款。

创建合约时可选择争议处理方式：默认双方协商，也可预先指定独立的仲裁钱包。Mock 托管中，双方可共同决定放款或退款；指定仲裁钱包还可单独裁决。链上程序和 Web 已实现两种规则；签名持久化、finalized 对账及页面恢复已通过本地验证器验收。链上争议能力默认关闭，当前仅允许明确批准的 localnet 配置开启。详见[迭代 2 交付记录](docs/iteration-2-delivery.zh-CN.md)。

## 系统设计

![Vesti 系统概览](docs/assets/diagrams/system-overview.png)

系统将协作状态与资金托管状态分离：

- 应用负责合约、里程碑、证明历史、申请、评论、争议和事件时间线。
- 托管边界负责注资和付款执行；统一适配器用于保持 Mock 与链上流程的行为一致性。
- 授权和状态转换统一在服务层执行，页面和 API 路由不得自行定义业务规则。
- 证明提交与合约事件采用只追加记录；资金操作使用幂等键和唯一交易签名。
- 链上交易先由钱包签名，确认后再进行对账；只有对账成功，本地资金状态才会推进。

## MVP 边界与就绪状态

当前仓库包含 Mock 托管流程，以及实验性的 Solana 钱包签名注资和付款流程。争议资金出口已在本地验证器验证；新版本尚未升级到 Devnet，也未完成真实钱包端到端验收。产品暂不提供法币支付、KYC、法律仲裁、多链结算或生产级链上争议处理。
